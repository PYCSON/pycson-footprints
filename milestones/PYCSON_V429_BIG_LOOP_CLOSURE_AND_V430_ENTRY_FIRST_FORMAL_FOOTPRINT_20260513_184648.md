# 1. One-Sentence Project Definition

PYCSON is a long-term AI-assisted market research and decision-support system for CS2/CSGO skin market analysis. It is designed to transform fragmented market data, local price records, candidate evidence, risk controls, and user-facing display logic into a structured, auditable, human-in-the-loop research terminal.

It is not an automatic trading bot.

It does not execute trades.

It does not automatically buy, sell, or place orders.

Its primary outputs are research-oriented signals such as WATCH, REVIEW, SKIP, and STRONG_WATCH, not direct execution commands.

# 11. Core System Identity

PYCSON is not a simple script.

It is not only a UI.

It is not only an EV calculator.

It is not only a local CSV reader.

It is better understood as a staged, auditable decision-support system.

Its layers include:

1. Data layer.
2. Rules layer.
3. Calculation layer.
4. Search layer.
5. Decision layer.
6. Display layer.
7. Audit layer.
8. Safety layer.

Each layer has a different responsibility. A lower layer must not pretend to complete the work of a higher layer.

---

# 12. Data Layer

The data layer is responsible for finding and reading possible data sources.

It may include:

- Local CSV files.
- Local JSON files.
- Cached exports.
- Historical price files.
- Candidate files.
- Previous pipeline outputs.
- Platform-derived records.
- User-provided evidence.

The data layer does not decide that a file is trustworthy.

A file being readable does not mean it is valid.

A file containing price-like columns does not mean it can drive EV.

The data layer only creates structured input for later review.

---

# 13. Rules Layer

The rules layer is responsible for interpreting CS2/CSGO market structure.

It may include:

- Rarity.
- Collection.
- Trade-up rules.
- Output pool logic.
- StatTrak distinction.
- Wear and float categories.
- Item identity.
- Candidate eligibility.

This layer is sensitive because mistakes here can create fake opportunities.

A wrong collection mapping can break the output pool.

A wrong rarity mapping can break probability.

A wrong wear mapping can break price selection.

A wrong item identity can make the entire EV calculation meaningless.

---

# 14. Calculation Layer

The calculation layer is responsible for mathematical reasoning.

It may include:

- Probability.
- Expected value.
- ROI.
- Fee-adjusted value.
- Risk-adjusted value.
- Slippage assumptions.
- Price freshness.
- Liquidity risk.
- Worst-case loss.
- Break-even analysis.

However, calculation is not enough. A mathematically high value is meaningless if the inputs are wrong.

Paper EV is not executable profit.

# 15. Search Layer

The search layer is responsible for finding candidate combinations.

It may include:

- Candidate generation.
- Filtering.
- Sorting.
- Ranking.
- Risk screening.
- Duplicate rejection.
- Evidence matching.

Search can create many possibilities, but quantity is not quality.

A good search layer must reduce noise, not amplify it.
